# AriNav — 3-minute pitch outline
Editable five-slide basis. Render using the existing slide toolchain; this file is not yet a presentation export.

## Slide1 — A building you can ask (0:00–0:25)
Large product image, small title: “Ask. See. Navigate.”
Problem: people know their intention, not the building's room identifiers. Coffee, a machine, an accessible route, a changing corridor.
Speaker point: “We make the building respond to what you need.”

## Slide2 — One real task, end to end (0:25–1:10)
Real app screenshot/short clip. Ask for coffee or an actual target; show route and the working navigation view.
State visibly when position is simulated. Prefer one successful clear task over many controls.

## Slide3 — Helpful conversation, deterministic action (1:10–1:45)
Simple pipeline: text/voice → Claude → validated tools → shared state/router → map and audio.
Mention reference routing and optional precision mode without merging their guarantees.

## Slide4 — We test the experience, not just the algorithm (1:45–2:25)
Use up to three current verified numbers with exact scope. Show one negative case such as a wheelchair route with a closed lift and a correct no-route result.
No “all users/all buildings100%” claim. Distinguish scripted/live/model tests.

## Slide5 — Ready to explore (2:25–3:00)
Strong actual POV/overview image; optional real recap card.
What works today, one honest limitation, why the modular implementation is useful to industrial teams.
Close: “AriNav turns building data into a conversation—and that conversation into a route.”

Design: reuse AriNav identity, large type, little text, actual screenshots, no decorative statistics. Keep notes editable. Rehearse duration; the event also includes a brief Q&A.
